# Infrastructure

The site is static files in S3 behind CloudFront. `.github/workflows/deploy.yml`
syncs the files and invalidates the cache. This folder holds the one piece of
edge logic and is not uploaded to S3.

## Edge function (CloudFront Function)

`cloudfront-functions/edge.js` is generated by `npm run build` from
`edge.template.js` (it embeds a Bloom filter of every page and API file, so
it must be redeployed whenever pages are added or removed). It handles:

- **Markdown content negotiation.** `Accept: text/markdown` on any page is
  served that page's Markdown twin (`/path/index.md`) with
  `Content-Type: text/markdown` and `Vary: Accept`. Browsers still get HTML,
  also with `Vary: Accept`.
- **Agent-friendly 404s.** A missing page requested as Markdown gets a 404
  with a Markdown body linking to llms.txt, the sitemap and the docs. A
  missing `/api/` path gets a 404 with a JSON body; a write gets a JSON 405.
- **Docs redirects.** `/docs` and `/api` redirect (301) to `/developers/`.
- **Headers.** Content types for `.md`, `/api/` JSON and
  `/.well-known/api-catalog`, CORS for the API, and a `Link` header to each
  page's Markdown twin.

### Deploying

The deploy workflow publishes the function on every push to `main` when the
repository variable `CLOUDFRONT_EDGE_FUNCTION` is set to the function's name
(for example `ljwm-edge`). The workflow's AWS user then needs
`cloudfront:DescribeFunction`, `CreateFunction`, `UpdateFunction`,
`TestFunction` and `PublishFunction`. To deploy by hand:

```bash
infra/deploy-edge-function.sh ljwm-edge
```

Then, once, associate it with the distribution: CloudFront console,
distribution, Behaviors, the default behavior, Edit, Function associations.
Choose **CloudFront Functions** and `ljwm-edge` for both **Viewer request**
and **Viewer response**, and save. If another function is already on viewer
request, merge its logic into `edge.template.js` first (a behavior takes one
function per event).

### Checking it

```bash
curl -sS -i -H 'Accept: text/markdown' https://www.ljwebmanagement.com/
curl -sS -i -H 'Accept: text/html' https://www.ljwebmanagement.com/
curl -sS -i -H 'Accept: text/markdown' https://www.ljwebmanagement.com/does-not-exist
curl -sS -i https://www.ljwebmanagement.com/api/v1/does-not-exist.json
```

`npm test` runs the same checks against a local stand-in for CloudFront and
S3 (`test/helpers.js`).
